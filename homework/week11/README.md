## 一、 計算理論在研究什麼？

計算理論（Theory of Computation）從數學與形式邏輯切入，檢視計算的能力邊界與資源限制。依《數學、語言、機器與程式》的脈絡，可歸納為三個核心提問：

1. **可證明性（Provability）：** 是否能靠明確的公理與推論規則，系統性地推導出數學命題？
2. **可計算性（Computability）：** 針對所有合法輸入，是否存在能保證停機並給出正確結果的演算法？
3. **計算複雜度（Computational Complexity）：** 當問題可解時，所需的時間、空間等資源隨輸入規模成長的速度是否可接受？

這些方向分別連結了數理邏輯、λ 演算、圖靈機、形式語言階層，以及 P、NP 與 NP-Complete 等分類。

## 二、 形式化夢想與極限：希爾伯特計畫與哥德爾定理

### 1. 希爾伯特計畫
希爾伯特試圖為數學建立一套嚴謹的形式化基礎，讓推論過程能依循固定規則逐步展開，並證明該系統不會出現自相矛盾。例如給定初始事實與推論規則：

- 事實：`A`、`B`
- 規則：`A => E`、`B => F`、`E & F => H`

依序推得 `E` 與 `F` 後，即可進一步推出 `H`。形式系統希望將數學證明轉化為可檢驗的規則推導。

### 2. 羅素悖論
考慮集合定義：

`A = { x | x 不屬於 x }`

若追問 `A` 是否屬於自身：
- 若 `A ∈ A`，則違反定義中「不包含自身」的條件。
- 若 `A ∉ A`，則又符合條件而應歸入 `A`。

這顯示集合與邏輯規則若缺乏適當限制，便會從直觀敘述引出矛盾。

### 3. 哥德爾完備定理與不完備定理
兩者針對的層次不同，並不互相衝突：
- **哥德爾完備定理：** 在一階邏輯中，若命題在所有滿足公理的模型下皆為真，則必然存在形式證明可推導出該命題（語義有效與語法可證一致）。
- **哥德爾第一不完備定理：** 只要形式系統一致、可有效公理化且足以涵蓋基本算術，就會存在無法在系統內證明也無法否證的命題。
- **哥德爾第二不完備定理：** 符合上述條件的一致系統，無法僅憑系統內部的推論證明自身的相容性。

## 三、 以函數描述計算：丘奇的 λ 演算

λ 演算（Lambda Calculus）將「函數定義」與「代換化簡」視為計算的核心，不需要傳統命令式語言的迴圈或可變狀態。例如：

`(λx. x + 1) 3`

將 `3` 代入函數主體後，可化簡為 `3 + 1 = 4`。常見操作包含：
- **α-conversion（名稱轉換）：** 更改綁定變數名稱而不改變函數語意，例如 `λx. x` 等價於 `λy. y`。
- **β-reduction（β 化簡）：** 將實際引數代入函數本體進行求值，例如 `(λx. x + 1) 3` 化簡為 `3 + 1`。

此外，丘奇數（Church Numerals）可用高階函數編碼自然數，Y Combinator 則示範在缺乏原生遞迴語法時如何建構遞迴。**邱奇－圖靈論點（Church–Turing Thesis）**指出，直觀上可由有效程序計算的函數，皆可由圖靈機（與等價模型如 λ 演算）計算。

## 四、 計算機器模型與停機問題

### 1. 有限狀態機（Finite State Machine, FSM）
由有限狀態集合、輸入字母表、起始狀態、轉移函數與接受狀態組成。以判斷二進位字串中 `0` 的個數是否為偶數為例：
- 維護「偶數個 0」與「奇數個 0」兩種狀態。
- 讀到 `0` 時切換狀態，讀到 `1` 時維持原狀態；結束時若停在偶數狀態即接受。

FSM 適合用於正規表示式、詞法掃描與協定狀態管理，但受限於有限狀態數，無法處理需要無界記憶計數的語言。

### 2. 圖靈機（Turing Machine）
在有限狀態機基礎上加入一條可雙向讀寫的無限磁帶與讀寫頭。每一步依據目前狀態與磁帶符號決定寫入內容、讀寫頭移動方向（左、右或停留）以及下一個狀態。通用圖靈機則能模擬其他圖靈機與輸入，呼應現代可程式化電腦的設計精神。

### 3. 停機問題（Halting Problem）
問題在於是否存在一個通用演算法 `isHalt(program, input)`，能對任意程式與輸入正確判定其最終是否停止。透過反證法建構矛盾程式並自我輸入，可證明不存在通用的停機判定演算法，屬於**不可判定問題**。

## 五、 喬姆斯基階層與語言分類

喬姆斯基階層依形式文法產生式的限制程度，劃分出四個語言層級：

| 層級 | 語言類別 | 對應自動機模型 | 典型特徵與應用 |
| :--- | :--- | :--- | :--- |
| Type 3 | 正規語言（Regular） | 有限狀態機 | 詞法分析、正規表示式、簡單樣式比對 |
| Type 2 | 上下文無關語言（Context-Free） | 下推自動機 | 括號配對、程式語言語法結構（CFG / Parser） |
| Type 1 | 上下文相關語言（Context-Sensitive） | 線性有界自動機 | 需受限於環境條件的規則，如 $a^n b^n c^n$ |
| Type 0 | 遞歸可枚舉語言（Recursively Enumerable） | 圖靈機 | 圖靈機可辨識的通用語言範圍 |

例如 $a^n b^n$（$n \ge 1$）可由上下文無關文法 `S -> aSb | ab` 生成；而同時要求三種符號數量相等的 $a^n b^n c^n$ 則需要更強的表達能力。在編譯器設計中，通常先以詞法分析處理較低層級的 token，再以語法分析處理結構。

## 六、 計算複雜度：P、NP 與 NP-Complete

### 1. 類別定義
- **P：** 存在確定型演算法，可在輸入規模的多項式時間內求解的決策問題。
- **NP：** 給定候選解時，可在多項式時間內驗證是否成立的問題（等價於非確定型圖靈機在多項式時間內可決定的問題）。注意 NP 代表 *Nondeterministic Polynomial Time*，而非「非多項式時間」。
- **NP-Complete：** 同時屬於 NP，且 NP 中所有問題皆可在多項式時間內歸約到此類問題。

### 2. SAT 與多項式時間歸約
布林可滿足性問題（SAT）詢問是否存在一組布林變數賦值，使整個邏輯式為 `True`。例如：

`(x OR y) AND (NOT x OR NOT z)`

當 `x = 0, y = 1, z = 0` 時，各子句皆為 `True`，故可滿足。若以窮舉法測試 $n$ 個變數，最多需檢查 $2^n$ 種組合，隨變數增加呈指數成長。

**多項式時間歸約**是指在多項式時間內將問題 A 轉換為問題 B，使 B 的解法可用來解 A。**庫克－列文定理**證明 SAT 為 NP-Complete，將非確定型圖靈機的多項式時間計算編碼為布林可滿足性條件。目前 **P vs. NP** 仍為未解難題，列於 Clay Mathematics Institute 千禧年難題之中。

## 七、 小結與 Python 示範

計算理論提醒我們，算力提升無法跨越理論上的不可計算邊界（如停機問題），而在可計算範圍內，演算法設計與複雜度分析決定了問題是否能在合理時間內被解決。

```python
from itertools import product


def is_even_zeros(binary_str: str) -> bool:
    """使用有限狀態機概念判斷二進位字串中的 '0' 是否為偶數個。"""
    state = "EVEN"
    for ch in binary_str:
        if ch == "0":
            state = "ODD" if state == "EVEN" else "EVEN"
        elif ch != "1":
            raise ValueError(f"不合法的輸入字元: {ch}")
    return state == "EVEN"


def sat_brute_force(variables: list[str], clause_fn) -> dict[str, bool] | None:
    """列舉所有真值組合，尋找滿足布林公式的一組賦值。"""
    for values in product([False, True], repeat=len(variables)):
        assignment = dict(zip(variables, values))
        if clause_fn(assignment):
            return assignment
    return None


if __name__ == "__main__":
    sample_bits = "101100"
    print("偶數個 0 測試:", sample_bits, "->", is_even_zeros(sample_bits))

    # (x OR y) AND (NOT x OR NOT z)
    formula = lambda a: (a["x"] or a["y"]) and ((not a["x"]) or (not a["z"]))
    solution = sat_brute_force(["x", "y", "z"], formula)
    print("SAT 可滿足賦值:", solution)
